# Мультиверсионная сборка

Проект собирается сразу на несколько версий Minecraft из одного набора исходников.
Управляет этим [Stonecutter](https://stonecutter.kikugie.dev/).

## Поддерживаемые версии

Один джарник на группу версий — там, где Minecraft менял API, нужен отдельный джарник.

| Джарник | Совместимость | Java | Канал |
|---|---|---|---|
| `+1.20-1.20.1` | 1.20 – 1.20.1 | 17 | release |
| `+1.20.2-1.20.4` | 1.20.2 – 1.20.4 | 17 | release |
| `+1.20.5-1.20.6` | 1.20.5 – 1.20.6 | 21 | beta |
| `+1.21-1.21.1` | 1.21 – 1.21.1 | 21 | beta |
| `+1.21.2-1.21.4` | 1.21.2 – 1.21.4 | 21 | beta |
| `+1.21.5-1.21.8` | 1.21.5 – 1.21.8 | 21 | beta |
| `+1.21.9-1.21.11` | 1.21.9 – 1.21.11 | 21 | beta |

В имени файла стоит диапазон, а не одна версия: `lostcities-1.1.0+1.20-1.20.1.jar`.
Так по названию сразу видно, на что джарник встанет, без сверки с описанием.
Диапазон собирается из `mod.mc_releases` соответствующей секции, поэтому руками
нигде не дублируется. Версия мода внутри `fabric.mod.json` остаётся чистой — `1.1.0`.

Подпроекты Gradle при этом называются по одной версии (`:1.20.1`, `:1.21.11`) —
это то, под что собирается код.

Канал (`mod.release_channel` в `stonecutter.properties.toml`) — это то, чем файл
помечается при загрузке на Modrinth и CurseForge. Стабильными считаются только
1.20 – 1.20.4: на них порт отлажен дольше всего. Остальные версии собраны и
проверены, но живут в проекте меньше, поэтому идут бетами.

Один джарник на весь диапазон сделать нельзя: с 1.20.5 меняются подписи используемых
методов, а в 1.21 ещё и каталоги датапаков. Подробности — в комментариях у версионных
веток в коде.

## Команды

```bash
./gradlew buildAndCollect
```

Собирает все версии, джарники и исходники складывает в `build/libs/1.1.0/`.

```bash
./gradlew :1.21.1:build
./gradlew :1.21.1:runServer
./gradlew :1.21.1:runClient
```

Работа с одной версией. Каждая версия живёт в своём подпроекте, run-каталог у неё
свой (`versions/<версия>/run`) — миры между 1.20 и 1.21 несовместимы.

```bash
./gradlew "Set active project to 1.21.1"
./gradlew "Reset active project"
```

Переключает версию, под которую подсвечивается код в IDE. Перед коммитом нужно
вернуть активную версию обратно (`Reset active project`), иначе в диффе окажутся
переставленные комментарии препроцессора. Задачу переключения нельзя запускать
в одной команде со сборкой — Gradle ругается на неявную зависимость.

## Где что настраивается

- `settings.gradle.kts` — список версий
- `stonecutter.properties.toml` — версия мода и по секции на каждую версию MC:
  yarn-маппинги, версия Fabric API, диапазон совместимости для `fabric.mod.json`
- `build.gradle.kts` — общий скрипт сборки, применяется к каждой версии
- `gradle.properties` — только опции самого Gradle

Версия мода и версия Minecraft в `fabric.mod.json` подставляются при сборке,
а `LostCityMod.VERSION` читает их через FabricLoader — руками нигде не дублируются.

## Версионные ветки в коде

Различия между версиями помечаются комментариями Stonecutter. Неактивная ветка
закомментирована, компилируется всегда ровно одна:

```java
//? if >=1.20.5 {
/*lootable.setLootTable(RegistryKey.of(RegistryKeys.LOOT_TABLE, lootId));
lootable.setLootTableSeed(seed);
*///?} else
lootable.setLootTable(lootId, seed);
```

Таких мест намеренно мало (сейчас два). Где можно, используется API с одинаковой
подписью во всех версиях — так меньше кода, который может разъехаться:

- высота мира — `Heights.topY()` через `getBottomY() + getHeight()` вместо
  `getTopY()`, который в 1.21.2 стал `getTopYInclusive()` со сдвигом на единицу
- спавнеры — `setEntityType()` вместо ручной сборки NBT
- реестры — `getOptional()` вместо `get()`/`getOrThrow()`
- `Identifier.of()` вместо конструктора
- свойства стен — `Properties.*_WALL_SHAPE` вместо `WallBlock.*_SHAPE`

## Проверка версии

Автоматической проверки нет: миксинов в порте сейчас нет, а компилятор ловит всё
остальное. Проверка ручная — `runServer` (стартует ли, нет ли исключений и
`Requested chunk` в логе) и `runClient` с осмотром мира. Прогон клиентов по всем
версиям — `tools/test-clients.sh`.

## Одинаковость генерации между версиями

Разметка городов на всех версиях одинаковая: `isCityCenter` и радиус зависят
только от координат чанка, без сида мира и без чего-либо версионного. На одних
координатах город будет в том же месте и того же размера.

Рельеф под городом — разный, потому что ванильный шум генерации между 1.20 и 1.21
менялся. От высоты террейна считается `cityLevel`, поэтому этажность и стыки
будут отличаться. Добиться тут совпадения невозможно, это решает Mojang.
